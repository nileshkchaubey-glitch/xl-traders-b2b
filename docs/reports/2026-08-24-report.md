# Storefront now matches the design prototype on four screens — 20–24 Aug 2026

The storefront has been rebuilt screen by screen against the Claude Design
prototype. The method changed partway through and that is the main reason
progress moved: instead of reading the prototype's markup, I started **serving
the standalone HTML in a browser and reading its computed styles**. Reading
markup had silently missed an entire red navigation bar under the desktop
header, and had produced a white identity card on Account where the prototype's
mobile version is a full-bleed dark panel. Both were found within minutes of
putting the two side by side.

Home, the footer, Account and the catalogue now match. Product detail and Cart
have not been compared yet.

## Shipped

**[#177](https://github.com/nileshkchaubey-glitch/xl-traders-b2b/pull/177) — the
mobile footer is gone, and Account carries what it used to say**

The prototype has no mobile footer at all — measured, not assumed. On a phone
ours wrapped into a cramped four-line block that collided with the back-to-top
button. It is now desktop-only. Everything it carried — address, phone, email,
hours, ordering terms, copyright — moved to the Account screen, which is where
the prototype puts it, and each one was checked as still reachable on a phone
afterwards.

Account itself was rebuilt from measured values at both screen sizes, because
they are genuinely different layouts: a dark full-bleed panel on mobile, a
280-pixel sidebar beside a content column on desktop. It is one piece of code,
not two — the sidebar measures 242 pixels inside, exactly the prototype's
number. No new typography sizes were invented; two of the mappings turned out
to be exact matches for sizes already in the system.

Also in this PR: the Home page tail you flagged — the sign-in and bulk-quote
banners at the bottom — is not in the prototype and is removed. Home went from
230 lines to 67.

**[#178](https://github.com/nileshkchaubey-glitch/xl-traders-b2b/pull/178) — the
catalogue title bar and filter sidebar**

The catalogue header is now the prototype's: on a phone, a back arrow, the
category name with a count beneath it, and a "Filter" pill that shows a red dot
when filters are active. On desktop the count sits on the same baseline as the
title, with sort and view controls pushed right. The breadcrumb is desktop-only,
because the prototype's mobile catalogue uses a back arrow instead.

The sidebar was rebuilt to the measured card — all 22 category rows now measure
exactly 28 pixels, matching the prototype. They were 34 until I found the cause:
the category icon was 20 pixels, not the padding.

The sidebar's search box is removed. It was not a second capability — the header
search writes the same URL parameter this page already reads, and the active
filter chips still show and clear a search.

**Earlier in the week** — #170 through #176 derived the type scale from the
prototype rather than inventing one, fixed the page shell to a single rule
capped at 1440 pixels, rebuilt the catalogue's category rail and grid, and added
two automated checks that fail the build if the new rules are broken.

## Open questions

**Does the product-count ban cover the catalogue's results count?** Our rules
ban "SKU / product counts" outright, and the catalogue renders "139 products".
That string predates this work — I moved it, I did not add it — and the practice
so far has treated a functional results count as different from a marketing
boast. I did not loosen the rule or delete the count. Say the word and I will
drop it, leaving only "Rates after sign in".

## Known gaps

- **One commit went straight to `main`, bypassing review.** `952534c`, the
  desktop category navigation bar. I checked out `main` after a merge and never
  branched. The tests passed and the code is fine, but it broke the project's
  own rule and I have not reverted it — that is your call.
- **Product detail and Cart have not been compared** against the prototype yet.
  Those are the two screens most likely to still be wrong.
- **Account's order history is a placeholder.** The three statistics render em
  dashes. That is the prototype's own treatment for a signed-out visitor, and
  accurate for us — there is no order-history feature yet.
- **Four things in the catalogue sidebar deliberately differ** from the
  prototype and are documented in the code: no per-row counts, category groups
  are kept, the card stays pinned while scrolling, and the minimum-order /
  per-piece-rate / material filters are not built. The last one needs database
  work, not layout work.
- **Category images are hosted on Google Drive** and fail to load on a local
  machine while working fine in production, so no image-dependent design can be
  judged from a local screenshot. Unresolved.
